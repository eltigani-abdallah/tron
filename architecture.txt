ARCHITECTURE DU PROJET (Tron)
Dernière mise à jour: 2026-07-28

Objectif
========
- Engine.dll (C++ / Direct3D 11) : le moteur.
- Game.exe : le jeu, qui n’utilise que l’API publique de Engine.dll.
- Assets/ : ressources runtime (shaders, textures, meshes…).
- Build : CMake + MSVC (Visual Studio 2022 x64), sortie des binaires dans build-msvc/bin/<Config>/.

FRONTIÈRE DLL (règles)
======================
- Game.exe inclut uniquement Engine/Public/EngineAPI.hpp.
- Game.exe ne connaît pas D3D11 (pas de ID3D11* côté jeu).
- Engine.dll expose une C API:
  - Engine_Create / Engine_Destroy / Engine_Tick
  - Engine_Resize
  - Engine_OnWin32Message (le jeu forward les messages Win32)
  - Engine_GetFrameStats (stats pour debug overlay côté jeu)
- Les objets internes du moteur restent opaques à l’extérieur (EngineHandle).


ARCHITECTURE CIBLE (plan long terme)
====================================
À mesure que le projet avance, Engine/Private s’étendra vers une structure plus complète:

Engine/Private/
│
├── Core/                             (memory, logging, threading, serialization)
├── Application/                      (game loop stages + state machine)
├── Math/                             (Vec/Mat/Quat, etc.)
├── Scene/                            (scenes, load/unload)
├── Renderer/
│   ├── Resources/                    (textures, samplers, constant buffers, meshes…)
│   ├── Materials/                    (materials/pipeline states)
│   ├── PostFX/                       (post-processing)
│   └── Shaders/                      (shader manager, reflection, hot reload)
├── Camera/                           (free/FPS/third-person)
├── Physics/
│   └── Collision/                    (AABB/Sphere/Ray + broadphase)
├── Particles/                        (emitters, pools, renderer)
├── UI/                               (debug UI + runtime UI)
├── Resources/                        (asset DB, loaders, caching, dedup)
└── Scripting/                        (Script base class Unity-like + runtime)


CONVENTIONS
===========
- Headers: .hpp (uniformisé)
- API publique: minimaliste et stable, pas de STL exposée via la DLL
- ECS: sparse-set + queries “iterate smallest dense + sparse lookup”
- Renderer: séparation progressive (ShaderManager, Mesh/Material, puis ResourceManager)
